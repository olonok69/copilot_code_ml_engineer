# sanitise-diff

## When to use

- Before claiming ready to hand off / commit.
- After staging a change (`git add`).
- User asks to sanitise or scrub the diff.

## Procedure

1. Inspect **staged** diff; consider **added** lines only (`+`), not removals.

```bash
git diff --cached
# or: git diff --cached | grep '^+' | grep -v '^+++'
```

2. Flag hits for (adapt patterns to repo `CONVENTIONS.md` / policy):

   - Secrets: API keys, tokens, passwords, private URLs with embedded creds.
   - Forbidden names / customer identifiers (from local policy).
   - Internal ticket ids embedded in **code** (docs under `data/changes/` may allow them).
   - Agent self-attribution (“Generated by …”, “Co-Authored-By: Copilot/Claude”, etc.) in shipped artifacts.

3. Exclude intentional local-only / gitignored paths from panic; still report them if staged by mistake.

4. Fix or unstage problems; re-run until clean.

## Output format

```text
Sanitise report
- Staged files: …
- Added-line scan: CLEAN | HITS
- Hits: <file:reason> …
- Actions taken: …
- Ready for human handoff: yes/no
```

Never skip because “this one looks clean.”

## ⚠️ Where the name list lives

The blocklist itself is **client data**. Keeping it inline means the file whose job is to
catch client names is the one file guaranteed to contain all of them — and that file gets
copied into examples, pasted into tickets and shipped in onboarding packs.

Keep the names in a **gitignored** side file (`.sanitise-names`, one name per line) and have
the skill read it. The skill is then publishable; the list never leaves the machine.

```bash
# .gitignore
.sanitise-names
```

Same reasoning as every other per-machine file in this methodology: the *mechanism* is
shared, the *content* is not.

## Invocation per surface (GitHub Copilot)

All surfaces. On the cloud agent it runs on the agent's own branch before the draft PR is ready for a human.

- **Copilot CLI:** type `/sanitise-diff` or let the agent pick it from the `description`. Manage with `/skills` or `copilot skill list|add|remove`.
- **VS Code (Copilot or Local harness):** `/sanitise-diff` in chat; manage in **Chat: Open Customizations**.
- **Copilot cloud agent / code review:** automatic selection only (by `description`).
- ⚠️ The Copilot CLI does **not** read `~/.claude/skills/` (VS Code does). A personal copy goes in `~/.copilot/skills/sanitise-diff/` (or `~/.agents/skills/`), or register the folder with `copilot skill add <dir>` / `COPILOT_SKILLS_DIRS`. Project copy: `.github/skills/sanitise-diff/SKILL.md`.
- Frontmatter is Copilot-valid: `name` equals the folder name (lowercase-hyphen — VS Code silently drops a mismatch), `description` ≤ 1024 characters, no `trigger:` key.
